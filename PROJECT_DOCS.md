## 1. Концепція та призначення

**Фінік** — десктопна бухгалтерська система для МСБ в Україні. Ключові правила:

| Принцип                      | Реалізація                                                                                                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Точність**                 | Усі суми — цілочисельні копійки (`int64_t`). `double/float` для грошей **суворо заборонені**.                                                          |
| **Подвійний запис**          | Кожна операція — одна або більше кореспонденцій у `ledger_entries`. Сума дебетів завжди дорівнює сумі кредитів.                                        |
| **Незмінність проведення**   | Проведений документ неможливо відредагувати без зняття з проведення (`unpost`).                                                                        |
| **Захист закритого періоду** | Дата `closed_through` блокує будь-яке редагування проведених документів до цієї дати включно.                                                          |
| **Ізоляція шарів**           | `fin_core` (бізнес-логіка) не знає про `QWidget` або UI.                                                                                               |
| **Контроль цілісності**      | `IntegrityChecker` верифікує нульовий баланс, відповідність складу рахунку 281 та балансу необоротних активів.                                         |
| **Цільовий режим**           | Одне робоче місце, локальний SQLite. Ролі — по черзі на одному файлі, не клієнт–сервер. XML декларацій ДПС — каркас, не подача (ПН XML — для M.E.Doc). |

## 4. Схема бази даних

База даних зберігається у файлі `*.fin` (SQLite 3, WAL-режим). Поточна версія схеми: **v26**.

### Ключові таблиці

| Таблиця                              | Призначення                                                                                              |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| `accounts`                           | План рахунків (ієрархія, код, назва, `is_folder`, `subconto_kinds`)                                      |
| `documents`                          | Заголовки первинних документів (тип, дата, номер, counterparty_id, employee_id, ...)                     |
| `document_lines`                     | Рядки документів (debit/credit account, amount_cents, nomenclature_id, quantity_milli, vat_rate_bp, ...) |
| `ledger_entries`                     | Головна книга (один рядок = одна кореспонденція, тільки проведені документи)                             |
| `inventory_movements`                | Складські рухи (quantity_milli, cost_cents) — зв'язані з ledger_entries                                  |
| `counterparties`                     | Контрагенти (ЄДРПОУ, назва, тип покупець/постачальник)                                                   |
| `contracts`                          | Договори контрагентів                                                                                    |
| `nomenclature`                       | Номенклатура товарів та послуг                                                                           |
| `warehouses`                         | Склади та торгові точки                                                                                  |
| `bill_of_materials` + `bom_lines`    | Специфікації виробів (BOM)                                                                               |
| `fixed_assets`                       | Картки основних засобів                                                                                  |
| `intangible_assets`                  | Картки нематеріальних активів                                                                            |
| `low_value_items`                    | Картки МШП (рахунок 22)                                                                                  |
| `employees`                          | Довідник персоналу (РНОКПП, оклад, ознака інвалідності)                                                  |
| `currencies`                         | Валюти та курси НБУ                                                                                      |
| `users`                              | Облікові записи (PBKDF2-HMAC-SHA256 хеш пароля, роль)                                                    |
| `subconto_kinds` + `subconto_values` | Аналітичний облік у розрізі субконто (контрагент, працівник тощо)                                        |
| `audit_log`                          | Журнал дій (хто/коли/що змінив)                                                                          |
| `schema_migrations`                  | Протокол застосованих міграцій                                                                           |

### Налаштування SQLite при кожному з'єднанні

```sql
PRAGMA foreign_keys = ON;       -- контроль цілісності зовнішніх ключів
PRAGMA journal_mode = WAL;      -- дозволяє конкурентне читання
PRAGMA synchronous = NORMAL;    -- баланс надійності та швидкості
PRAGMA busy_timeout = 5000;     -- тайм-аут блокування 5 сек
```

### Система міграцій

Кожен крок міграції — іменований SQL-рядок або набір операторів в `Database::migrate()`. Версія схеми зберігається в таблиці `schema_migrations`. Метод порівнює поточну версію з `kSchemaVersion = 26` та застосовує недостатні кроки.

## 6. Підсистема проведення документів

### 6.1. DocumentValidator

Файл: [`DocumentValidator.cpp`](src/fin/posting/DocumentValidator.cpp)

Валідатор виконує перевірки **до** запису у Головну книгу:

- Наявність обов'язкових полів (контрагент для торгових операцій, підзвітна особа для авансового звіту, номенклатура для складських)
- Коректність кореспонденцій рахунків (напр., кредит авансового звіту — тільки 372x)
- Заборона проведення в закритому періоді
- Перевірка невід'ємних залишків на складі (при списанні)
- Підтвердження позитивних сум

### 6.2. PostingEngine

Файл: [`PostingEngine.cpp`](src/fin/posting/PostingEngine.cpp)

Атомарний запис у БД через `BEGIN IMMEDIATE` транзакцію:

1. Виклик `DocumentValidator::validate()`
2. Запис рядків у `ledger_entries`
3. Автоматичне субконто-заповнення (контрагент, працівник) для відповідних рахунків
4. Якщо рядок дебетує рахунок запасів (`201`, `202`, `203`, `281`, `22`, `26`) → `InventoryCosting::receive()`
5. Якщо рядок кредитує рахунок запасів → `InventoryCosting::takeOutgoingCost()` (середньозважена)
6. Механізм залікування авансів (`AdvanceOffset`) для рахунків 361/631/371/681

### 6.3. InventoryCosting

Файл: [`InventoryCosting.h/cpp`](src/fin/posting/InventoryCosting.cpp)

- Метод обліку: **середньозважена собівартість** (партійний FIFO не реалізовано)
- `receive(item, qty, amount)` — оприбуткування партії
- `issue(item, qty)` → `Result<Money>` — розрахунок і списання собівартості

### 6.4. AdvanceOffset

Файл: [`AdvanceOffset.h/cpp`](src/fin/posting/AdvanceOffset.cpp)

Автоматичний залік авансів при реалізації та надходженні:

- Покупці: `Дт 681 — Кт 361` (залік отриманого авансу при продажу)
- Постачальники: `Дт 631 — Кт 371` (залік виданого авансу при надходженні)

## 11. Безпека та розмежування доступу

Файли: [`auth/Access.h/cpp`](src/fin/auth/Access.cpp), [`auth/Password.h/cpp`](src/fin/auth/Password.cpp)

### Ролі

| Роль         | Можливості                                                          |
| ------------ | ------------------------------------------------------------------- |
| `Admin`      | Повний доступ + управління користувачами + зміна закритого періоду  |
| `Accountant` | Створення/редагування/проведення документів, звіти, друк, демо-дані |
| `Cashier`    | Тільки касові операції (301) та перегляд                            |
| `Viewer`     | Тільки перегляд документів і звітів                                 |

### Правила безпеки

- Паролі зберігаються як **PBKDF2-HMAC-SHA256** (сіль + ітерації), порівняння constant-time
- Токен Monobank у `company_profile` зберігається в запечатаному вигляді (`v1:…`); UI не показує існуюче значення
- Прапорець `allow_negative_stock` — у **Налаштуваннях** (`SettingsDialog`) + `Access::requireEditCompany`; картка підприємства зберігає значення без окремого чекбокса
- Перевірка прав реалізована **на рівні репозиторіїв та сесії** (`Access::require*()`), а не тільки приховуванням кнопок в UI
- Прив’язка субконто до рахунку (`SubcontoRepository::setForAccount`) — теж зміна довідника: `Access::requireEditDirectories`
- Запис рядків (`replaceLines` / `updateLineAmounts`) дозволений лише для непроведеного документа; виняток — `replaceLines(..., allowPosted=true)` **лише для проведеної податкової накладної** (реєстрація в ЄРПН). `setPosted` / `setEdoPayload` / `setFiscalPayload` / `setVatRegistration` теж вимагають `Access::requireDocumentWrite`
- Заборонено деактивувати або понижувати права **останнього активного адміністратора**
- Журнал дій (`audit_log`) фіксує: хто, коли, що створив/змінив/видалив
- Ролі не означають одночасний доступ по мережі: один файл SQLite — один активний запис

## 12. Електронний документообіг та банківська виписка

### ЕДО: Податкові накладні (ЄРПН)

Файл: [`edo/TaxInvoiceXml.h/cpp`](src/fin/edo/TaxInvoiceXml.cpp)

- **Експорт** ПН у форматі XML (формат ДПС України)

Файл: [`edo/DeclarationXml.h/cpp`](src/fin/edo/DeclarationXml.cpp)

- **Генератор XML-декларацій** (`DeclarationXml`): каркас конверта ДПС (`DECLAR` / `DECLARHEAD` / `DECLARBODY`) з кодами ДПІ з картки підприємства. Вбудованих XSD ДПС немає — перевіряється лише структура (`validateDeclarStructure`).
- **Експорт Декларації з ПДВ**: **каркас** (рядки R011 / R101 / R18) на основі Відомості ПДВ; база рахується зі ставки ПДВ з картки підприємства (без ставки експорт не виконується). Повне тіло за XSD ДПС — у плані, тому файл **не готовий до подачі**.
- **Експорт Фінансового звіту**: вивантаження Балансу (форма 1-м) для малого підприємництва.
- Без заповнених кодів ДПІ (`C_REG` / `C_RAJ` / `C_STI_ORIG`) будь-який експорт DECLAR відхиляється.

### Банківська виписка

Файл: [`bank/StatementImport.h/cpp`](src/fin/bank/StatementImport.cpp)

- Імпорт виписки у форматах **CSV** та **XML** (банківські формати)
- **Експорт вихідних платежів** (`PaymentExport.h/cpp`): CSV у стилі iBank/iTiny для завантаження в клієнт-банк (Приват24 / Ощадбанк тощо); кнопка на сторінці виписки 311

## 18. Контроль цілісності даних

Файл: [`integrity/IntegrityChecker.cpp`](src/fin/integrity/IntegrityChecker.cpp)

`IntegrityChecker::verify()` перевіряє:

1. **SQLite**: `PRAGMA foreign_keys = ON`, `PRAGMA quick_check`, `PRAGMA foreign_key_check`
2. **Нульовий баланс**: сума Дт = сумі Кт у `ledger_entries` за будь-який період
3. **Відповідність складу**: `inventory_movements.cost_cents` ↔ сальдо `281` в `ledger_entries`

## 22. Довідка (Help)

Вбудована довідка компілюється у бінарний файл як Qt-ресурс (`help/help.qrc`). Відкривається клавішею **F1**.

Скріншоти в `help/shots/` оновлюються ціллю **`fin_shots`** (`src/tools/CaptureHelpShots.cpp`): демо в пам’яті → `QWidget::grab()` → PNG. Після змін UI:

```bash
cmake --build build --target fin_shots
QT_QPA_PLATFORM=offscreen ./build/fin_shots help/shots
cmake --build build --target Finik   # вбудувати нові PNG у qrc
```
