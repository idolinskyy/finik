# Дорожня карта «Фінік»

Актуально для **v0.1** (схема БД **v26**).
Мета етапу 1 — робоче місце бухгалтера МСБ в Україні (НП(С)БО / ПКУ), а не клон платформи 1С.
Етап 2 — далекий горизонт (платформа / ERP); **не в скоупі v0.1**.

Статуси: **є** · **частково** · **план**.

Детальний факт «що вже в коді» також у [PROJECT_DOCS.md](../PROJECT_DOCS.md) §23.

## Етап 1 — Бухгалтерія (Accounting)

### 1.1. Субконто (багатовимірна аналітика) — частково

**Є**

- Прив’язка видів субконто до рахунків (`account_subconto`, `SubcontoRepository`)
- Аналітика в проводках / `SubcontoTrialBalanceReport` / картка з `buildWithSubconto`
- **UI «ОСВ по субконто»** (Звіти + ПКМ з ОСВ): розріз за обраним lineNo
- Колонка «Субконто» в картці рахунку
- **UI прив’язки в Плані рахунків**: подвійний клік / ПКМ «Субконто…» — до 3 видів на рахунок (обов’язковість)
- Прив’язку змінює лише бухгалтер або адміністратор (`Access::requireEditDirectories`); невідомий вид субконто відхиляється
- Обов’язкові субконто перевіряються у всіх типах документів, включно з ручною операцією (БО) та введенням залишків (ЗС); виняток — згорнуті проводки закриття місяця (`PeriodResult`)

**План (поглиблення)**

- Довільні типи субконто (статті витрат тощо) без хардкоду видів у проведенні
- Ієрархічне розгортання ОСВ за всіма вимірами одночасно
- Редагування субконто безпосередньо в формах документів (де ще не заповнюється автоматично)

### 1.2. Мультивалюта (НП(С)БО 21) — є

**Є**

- Довідник валют і курсів, `NbuRateClient` (НБУ)
- Рахунки на кшталт 312 / розрахунки з нерезидентами в демо та плані рахунків
- **UI валюти/курсу** в товарних документах, послугах від постачальника та банківському платежі (автопідстановка курсу НБУ на дату)
- Суми в копійках UAH + валютний облік у документах/проводках (де реалізовано)
- Рахунки 714 / 944 у плані рахунків і закритті періоду
- Регламентна переоцінка монетарних статей на кінець місяця (`ExchangeDifferenceEngine`): 312 / 302 / 334 / 362 / 632; аванси 3712 / 6812 не переоцінюються; відсутність курсу НБУ — помилка
- Паралельний `currency_amount` у картці рахунку та ОСВ (валюта + валютне сальдо)

### 1.3. Виробництво (23, 20, 26, 91) — є

- BOM (`bill_of_materials` / `BomPage`) + кнопка «Створити вимогу-накладну» з `bomId`
- Списання матеріалів у виробництво, випуск на 26; based-on випуск↔вимога через BOM
- Середньозважена собівартість (не FIFO)
- Розподіл / закриття через місяць і фінрезультат
- Довідка `help/production.html`, демо в `DemoSeed`

### 1.4. Підзвіт (372) — є

- Документ `ExpenseReport`, субрахунки 372x, зв’язок з касою/банком
- Друкована форма № 841, UI, тести, `help/expense-report.html`

### 1.5. Кадри та зарплата — є (базовий+)

**Є**

- Кадрові накази (прийом / переведення / звільнення)
- Табель (П-5), payroll, ПДФО / ВЗ / ЄСВ, ПСП
- Відпускні та лікарняні (КМУ № 100; 5 днів за рахунок роботодавця)
- «На підставі» виплата (банк/ВКО) також з відпускних і лікарняних
- Друк П-6 і розрахункових листків з документа нарахування / журналу
- Підрозділ у картці працівника (+ через кадровий наказ)

**План (розширення)**

- Повні довідники графіків/підрозділів «як у ЗУП»
- Індексація доходів, П-7 та інші регламентні кадрові форми

### 1.7. Регламентована звітність і ЕДО — частково

**Є**

- Податкові накладні, XML для ЄРПН / M.E.Doc (`TaxInvoiceXml`)
- Експорт декларації з ПДВ (`buildVatDeclarationXml`)
- Баланс / фінрезультати (форми 1-м / 2-м) і XML (`buildBalance1MXml`)
- Книга доходів, відомості ПДВ у UI
- Об'єднана звітність: Розрахунок J/F0500111 + 4ДФ J/F0510411 + Д1 J/F0510111 + **Д5 J/F0510511** (трудові відносини)
- Декларація ЄП 3 групи: F0103308 / J0103508 (R13 з попереднього кварталу; ВЗ 1% R23–R25 для ФОП)
- Структурна перевірка DECLAR перед збереженням XML

**План**

- Повна валідація по XSD з реєстру ДПС (зовнішні схеми)
- Додаток Д6 (спеціальний стаж) та інші додатки єдиної звітності

## Етап 2 — Платформа / ERP (горизонт, не v0.1)

Ідеї на майбутнє, без зобов’язань по термінах:

1. **Метадані** — конфігуровані довідники/документи/регістри без перекомпіляції ядра
2. **Скрипти** — пісочниця обробників проведення (Lua/JS тощо)
3. **Клієнт–сервер** — PostgreSQL + app-server; зараз цільовий режим — локальний SQLite
4. **Студія форм** — візуальний конструктор (свідомо не робимо «конфігуратор 1С» без окремого рішення)
5. **ERP-модулі** — WMS, CRM/SCM, казначейство, публічне API для магазинів/маркетплейсів

Поки етап 1 не закритий по ПРРО / повній ДПС-звітності / глибшій аналітиці — етап 2 не стартуємо.
