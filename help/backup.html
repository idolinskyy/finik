Резервне копіювання та відновлення бази даних

Надійна безпека облікових даних — фундаментальний пріоритет системи «Фінік». Вся ваша бухгалтерія (довідники, первинні документи, проводки, податки, зарплата та журнал аудиту) зберігається у компактному локальному файлі бази даних SQLite.

Розташування бази даних

За замовчуванням база — файл finik.sqlite у каталозі Qt organizationName/applicationName (обидва Finik):

  • Linux: ~/.local/share/Finik/Finik/finik.sqlite
  • Windows: %APPDATA%\Finik\Finik\finik.sqlite
  • macOS: ~/Library/Application Support/Finik/Finik/finik.sqlite

Якщо потрібно змінити розташування (інший диск), виберіть Файл → Налаштування…. Після зміни шляху перезапустіть програму. Не кладіть робочий файл на мережевий диск «для спільного доступу»: одночасний запис з двох сеансів SQLite не підтримує. Токени Monobank і Checkbox захищені файлом finik-secrets.key у тому ж каталозі: відновлення бази на іншому ПК вимагає ввести токени знову.

Створення резервної копії (Бекап)

Щоб створити резервну копію, виберіть у головному меню: Файл → Резервна копія… та вкажіть шлях до папки (наприклад, на зовнішній USB-диск або в синхронізовану хмарну папку Google Drive / Dropbox).

  • Гаряче копіювання без зупинки роботи: копія створюється під час роботи програми — немає потреби виходити з Фініка.
  • Цілісність даних: резервна копія фіксує узгоджений стан балансу на момент виклику команди.
  • Рекомендація: створюйте резервну копію наприкінці кожного робочого тижня та обов'язково перед процедурою закриття місяця чи завантаженням оновлень.

Безпечне двоетапне відновлення (Staged Restore)

Відновлення бази даних доступне виключно користувачам з роллю Адміністратор через пункт меню Файл → Відновити з копії….

На відміну від звичайних програм, які просто перезаписують файл (ризикуючи втратити дані, якщо копія виявиться пошкодженою), у Фініку реалізовано відмовостійкий триступеневий механізм:

  1. Верифікація копії: система спочатку відкриває вибраний файл, перевіряє цілісність структури бази та сумісність версії. Якщо файл пошкоджений, відновлення блокується.
  2. Підготовка та захисний знімок: перевірений файл готується до підстановки, а поруч система автоматично створює аварійний страховий знімок поточної бази — finik.sqlite.before-restore. Навіть у разі помилки адміністратора стара база завжди зберігається поруч!
  3. Фіналізація при старті: програма виводить повідомлення про успішне планування та пропонує перезапустити систему. Під час запуску процес підмінює файл бази даних на новий і відкриває його.
Порада: файл finik.sqlite.before-restore зберігається в каталозі даних програми. Якщо ви випадково відновили не той бекап, його можна легко повернути, перейменувавши страховий файл у робочу назву.
