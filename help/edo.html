Електронний документообіг (ЕДО): XML податкових накладних

Система «Фінік» підтримує повний цикл роботи з електронними копіями податкових накладних у форматі XML для обміну з податковими органами та контрагентами через системи M.E.doc, Соната, Вчасно та офіційний Електронний кабінет платника податків (Кабінет ДПС).

Чому Фінік не зберігає КЕП і не підписує?

Кваліфікований електронний підпис (КЕП) — це надзвичайно чутливий об'єкт. Його зберігання у бухгалтерській програмі, що розміщується на робочій станції, становить неприпустимий ризик безпеки (наприклад, компрометація ключа директора або головного бухгалтера).

Тому «Фінік» реалізує принцип відповідальності без зберігання ключа:

  • Формує структурований XML-файл ПН із усіма необхідними реквізитами за форматом ДПС;
  • Обчислює та зберігає контрольну суму файлу (хеш SHA-256) для перевірки цілісності на стороні отримувача;
  • Не підписує файл. Підписання відбувається в спеціалізованій програмі M.E.doc або через вебінтерфейс Кабінету ДПС, де ваш КЕП-носій (токен, флешка) безпосередньо в руках відповідальної особи.

Регламентовані XML (DECLAR)

Експорт об'єднаної звітності, ЄП, балансу 1-м і каркасу декларації з ПДВ вимагає заповнених кодів ДПІ у картці підприємства (регіон, район, код ДПІ). Без них експорт блокується з повідомленням.

Декларація з ПДВ зараз формує лише ключові рядки (R011 / R101 / R18) з базою від ставки ПДВ у картці підприємства — це каркас для перевірки, не повна форма за XSD ДПС і не файл для подачі. Перед подачею перевіряйте (і здавайте) файл у Кабінеті ДПС / M.E.Doc.

Ставка ПДВ у картці має бути заповнена (більше 0). Якщо ставки немає, експорт декларації відхиляється — програма не підставляє 20% «за замовчуванням», щоб не сформувати неправильну базу оподаткування.

Експорт XML вихідних (outgoing) ПН

  1. Відкрийте проведену Податкову накладну з Журналу документів.
  2. Натисніть кнопку «Експорт XML» у формі ПН.
  3. Вкажіть папку та ім'я файлу для збереження.
  4. Отриманий XML-файл передайте до M.E.doc або Кабінету ДПС для підписання та реєстрації в ЄРПН.

Система зберігає шлях до експортованого XML і контрольну суму файлу (SHA-256), щоб можна було перевірити, що файл не змінювали після вивантаження.

Імпорт вхідних (incoming) ПН від постачальників

Якщо постачальник передав вам XML-файл своєї вихідної ПН (наприклад, через M.E.doc або поштою), ви можете імпортувати її в «Фінік»:

  1. У Журналі документів виберіть Дія → Імпорт XML ПН…
  2. Вкажіть файл XML, отриманий від постачальника.
  3. Система перевіряє:
    • Структуру XML і наявність обов'язкових полів ПН (формат J12, без вбудованої перевірки XSD ДПС);
    • Чи ІПН/ЄДРПОУ продавця відповідає вашому ЄДРПОУ (вихідна ПН від вашого ж підприємства): якщо так — файл прикріплюється до існуючої ПН за номером без змін проводок;
    • Чи ІПН покупця відповідає ЄДРПОУ вашого підприємства: якщо так — автоматично створюється чернетка вхідної ПН з проводкою Дт 644 Кт 631 (ознака імпортованої ПН).
  4. Перевірте сформовану чернетку та проведіть її.
Контроль цілісності: при імпорті система обчислює SHA-256 отриманого файлу та зберігає його. Якщо файл модифікований або пошкоджений, хеші не збігатимуться, що буде сигналом для бухгалтера перевірити достовірність документа.

Статус «Зареєструвано в ЄРПН»

Після того як ПН зареєстрована в ЄРПН і ви отримали квитанцію №2 від системи ДПС, у формі Податкової накладної вкажіть Дату реєстрації та натисніть «Зареєструвати». Програма виконає проводку:

  • Вихідна ПН: Дт 643 Кт 641 — зобов'язання переходить у рядку розрахунків із бюджетом;
  • Вхідна ПН: Дт 641 Кт 644 — кредит підтверджується до відшкодування.

Проводка 641 рахунку формується датою реєстрації в ЄРПН (не датою ПН), що дозволяє коректно відображати міжмісячні реєстрації навіть після закриття звітного місяця.
